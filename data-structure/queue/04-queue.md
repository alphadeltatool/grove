## 백지 인출

### Q1. Queue는 어떤 순서로 데이터를 꺼내나? (FIFO가 뭔지)
FIFO(First In First Out) — 먼저 넣은 데이터를 먼저 꺼낸다. 은행 번호표, 줄서기처럼 먼저 온 순서대로 처리. 실무 예: 카프카 같은 메시지 큐, 작업(job) 큐, BFS 탐색.

### Q2. Queue를 배열로 구현하면 왜 원형(circular)으로 만들어야 하나?
Queue는 뒤(rear)로 넣고 앞(front)에서 뺀다. `front`에서 계속 빼주면 배열 앞쪽에 빈 자리가 쌓이는데, `rear`는 그걸 모르고 계속 뒤로만 전진하다가 배열 끝에 부딪힌다. 이때 앞쪽의 빈 자리를 재사용하려고 `rear`(그리고 `front`)를 `(index + 1) % 배열길이`로 감아서 0번으로 되돌리는 게 원형 큐. 안 그러면 실제론 빈 자리가 있는데도 "꽉 찼다"고 오판하게 됨.

### Q3. `front`, `rear`, `count` 세 값이 각각 왜 필요한가?
- `front`: 다음에 꺼낼(dequeue) 위치
- `rear`: 다음에 넣을(enqueue) 위치
- `count`: 현재 몇 개 들어있는지. `front`/`rear`만으로는 "꽉 찼다"와 "비었다"를 구분 못 함(원형이라 두 값이 같은 지점에서 겹칠 수 있어서) → 별도 카운터로 판단.

### Q4. Java에서 Queue 용도로 실무에 뭘 쓰나?
`ArrayDeque`(배열 기반, 대부분 가장 빠름) 또는 `LinkedList`(Queue 인터페이스 구현체). 멀티스레드 생산자-소비자 패턴이면 `BlockingQueue`(`LinkedBlockingQueue` 등) — 큐가 비었을 때 꺼내려는 스레드를 대기시켜주는 기능 내장.

## 대조 채점
- FIFO 개념·예시(카프카, 번호표)는 바로 나왔음.
- 막혔던 지점: 원형 큐의 `%` 필요성은 이해했지만 "어디서 넣고 어디서 빼는지" 방향이 처음엔 헷갈림(뒤에서 먼저 빼는 걸로 착각) → front=꺼내는 곳/rear=넣는 곳으로 정정 후 이해.
- `MyQueue.java` 직접 구현 완료: `objects`(배열) + `front`/`real`(rear, 코드상 변수명은 `real`로 되어있음)/`count` 방식, enqueue/dequeue/isEmpty 작성 후 컴파일·실행으로 wrap-around(rear가 배열 끝을 넘어 0으로 돌아옴) 확인.
