## 백지 인출

### Q1. Stack은 어떤 순서로 데이터를 꺼내나? (LIFO가 뭔지)
LIFO(Last In First Out) — 가장 나중에 넣은 데이터를 가장 먼저 꺼낸다. 접시를 쌓아올렸다가 맨 위부터 다시 가져가는 것과 같음. 실무 예: 브라우저 뒤로가기(최근 방문 페이지부터), 함수 호출 스택(재귀), 실행 취소(undo).
 
### Q2. Stack을 배열로 구현할 때 필요한 필드와 push/pop 로직은?
필드: 데이터를 담을 배열(`stackRoom`) + 맨 위 원소의 인덱스를 가리키는 `top`(초기값 -1 = 비어있음).
- `push(value)`: `top`을 1 증가시키고 그 자리에 값을 넣는다. `top == length-1`이면 꽉 찬 것.
- `pop()`: `top` 위치의 값을 꺼내고 `top`을 1 감소시킨다. `top == -1`이면 빈 스택.
- `peek()`: 꺼내지 않고 `stackRoom[top]`만 반환.

### Q3. Stack은 Queue처럼 `%` 연산(원형 처리)이 필요 없다. 왜?
Queue는 앞(front)에서 빼고 뒤(rear)에서 넣기 때문에 두 지점이 따로 움직여서 앞쪽에 빈 공간이 생기고, 그걸 재사용하려고 배열을 원형으로 감아야(`%`) 한다. Stack은 넣고 빼는 지점이 `top` 단 하나뿐이라 항상 같은 쪽 끝에서만 작업하므로 감을 필요가 없다.

### Q4. Java `Stack` 클래스 대신 실무에서 `ArrayDeque`를 권장하는 이유는?
`java.util.Stack`은 `Vector`(레거시 컬렉션)를 상속받아 모든 메서드가 `synchronized`로 걸려있음 — 단일 스레드에서도 항상 락 비용을 치러서 느림. `ArrayDeque`는 그 짐 없이 양쪽 끝에서 넣고 빼는 용도로 설계돼 더 빠르고, `push()`/`pop()`도 지원해 스택 대용으로 쓸 수 있음.
