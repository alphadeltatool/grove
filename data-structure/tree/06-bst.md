## 큰 그림 (시작 전 정리)
- `List`(인터페이스) ↔ `ArrayList`/`LinkedList`(구현체) 관계 — 정확히 답함.
- `Set`(인터페이스) 밑에 `HashSet`과 `TreeSet`이 형제 구현체로 있다. `HashSet`은 내부적으로 `HashMap`을 그대로 가져다 쓰고(위임, 해시 버킷 방식), `TreeSet`은 내부에 레드-블랙 트리를 갖고 항상 정렬된 순서를 유지한다. **"Hash"는 인터페이스가 아니라 저장 방식(기법)을 가리키는 말일 뿐** — `HashSet`이 실제로 구현하는 인터페이스는 `Set`이다.
  - ❓ "Hash를 구현한 게 HashSet"이라고 답함(Hash를 인터페이스로 착각) → 정정.

## 백지 인출 + 대조 채점

### Q1. Tree는 어떻게 생긴 구조인가?
**루트(root, 꼭대기에 있는 유일한 부모 없는 노드)에서 시작해서, 아래로 갈수록 여러 갈래로 갈라지고(branch), 더 이상 갈라지지 않는 끝(leaf, 리프)에서 멈추는 계층 구조.** 조직도(사장→팀장→팀원)나 파일탐색기 폴더 구조가 정확히 이 모양이다.
```
        A          ← 루트
       / \
      B   C        ← A의 자식
     / \   \
    D   E   F       ← 자식이 없음 = 리프
```
- ❓ 처음엔 "트리는 트리구조"라는 동어반복만 나옴 → 구체적 그림(위 다이어그램)으로 정정.

### Q2. 이진트리에서 "이진"은 뭘 제한하는 규칙인가?
**"이진(binary)" = 각 노드가 자식을 최대 2개까지만 가질 수 있다는 구조 제약, 그게 전부.** 크기를 비교해서 왼쪽/오른쪽으로 찾아가는 규칙은 "이진"의 뜻이 아니라, 그 위에 **이진탐색트리(BST)가 추가로 얹는 정렬 규칙**이다: 왼쪽 자식은 항상 나보다 작고, 오른쪽 자식은 항상 나보다 크다. 즉 **찾는 값이 지금 노드보다 크면 오른쪽, 작으면 왼쪽**으로 내려간다.
- ❓ "크기 비교해서 찾아가는 것"을 "이진"의 정의로 착각(사실은 BST 규칙) + 방향도 반대로 답함(크면 왼쪽이라고 함) → 예시 트리(`50/30/70/20/40/60/80`)에서 `60` 탐색을 손으로 트레이스하며 둘 다 정정.

### Q3. BST 탐색이 왜 평균 O(log n)인가?
**매 단계 비교할 때마다 한쪽 서브트리 전체를 통째로 버릴 수 있기 때문** — 배열의 이진탐색(반씩 버리기)과 완전히 같은 원리다. 위 예시 트리(원소 7개)에서 `60`을 찾는 데 `50→70→60` 딱 3단계면 끝났다.
- ✅ "반씩 버리고 찾으니 logN" — 힌트 없이 바로 정확히 답함, 배열 이진탐색과 스스로 연결함.
- (다음 단계 예고: 트리가 한쪽으로 치우쳐 자라면 이 O(log n)이 깨지고 O(n)이 된다 — 레드-블랙 트리 같은 균형트리가 필요한 이유.)

### Q4. 새 값(`65`) 삽입 로직은?
**탐색과 완전히 동일한 로직으로 내려가다가, 처음으로 만나는 빈 자리(null)에 새 노드를 붙인다.** `65` 삽입 시: `50`(65>50→오른쪽) → `70`(65<70→왼쪽) → `60`(65>60, 근데 60의 오른쪽이 비어있음) → 거기 `65`를 붙임.
- ✅ Q2에서 방향을 정정받은 직후 바로 정확히 적용함 (막힘 없이 전이됨).

### Q5. In-order 순회(왼쪽→나→오른쪽)가 왜 정렬된 순서를 만드는가?
**"왼쪽 서브트리를 통째로 먼저 끝내고 → 나 자신을 출력 → 오른쪽 서브트리를 통째로 끝낸다"를 각 노드마다 재귀적으로 반복하면, 결과적으로 작은 값부터 큰 값 순서로 출력된다.** 예시 트리 전체를 이 규칙으로 순회하면 `20,30,40,50,60,70,80` — 정확히 정렬된 순서. Day5에서 배운 "TreeSet은 항상 정렬 유지"가 바로 이 원리다.
- ❓ 재귀 개념 자체가 처음이라 전체 트리로는 못 풀었음(규칙 없이 임의로 추측) → **3노드 서브트리(20/30/40)로 축소해서 "보류(일시정지)→재개" 방식으로 콜스택을 손으로 완전히 트레이스**한 뒤에야 이해, 이후 전체 트리로 확장 성공.

## 구현 (`data-structure/tree/MyBST.java`) — 완료 ✅ (2026-08-16)
- **Node**: `value`(int) + `left`/`right`(Node) — 처음에 `left`/`right`를 `Object`로 잘못 선언해서 `current = current.left` 대입 시 컴파일 에러 발생 → `Node` 타입으로 정정.
- **insert()**: `root==null`이면 새 Node를 `root`에 직접 대입(중간에 `Node root = new Node(...)`로 지역변수를 새로 만들어 필드를 안 채우는 실수, `root.left`처럼 항상 루트 기준으로만 이동하려던 실수 등을 거쳐 정정) → `while(true)` + `current`(커서 변수)로 내려가며 빈 자리에 삽입. 직접 완성, 막힘 없이 컴파일 성공.
- **contains()**: `current.left = current;`처럼 **대입 방향이 반대**라 트리 자체를 훼손하는 버그(자기참조) + 무한루프 발생 → `current = current.left;`로 정정 완료.
- **inOrderTraversal() / inOrder(Node)**: 재귀 개념(자기 자신을 다시 호출, 종료조건 `node==null`)을 처음 코드로 옮기는 거라 여러 차례 트레이스(3노드 서브트리 → 콜스택 표 → 트리형 다이어그램)를 거친 뒤 직접 완성. "왼쪽 호출이 즉시 리턴됐다고 바깥쪽 호출까지 끝나는 게 아니다"는 게 핵심 이해 포인트였음.
- **실행 검증**: `50,30,70,20,40,60,80` 삽입 → `inOrderTraversal()` 출력이 `20,30,40,50,60,70,80`(정렬됨) 정확히 일치. `contains(60)=true`, `contains(65)=false` 확인.
