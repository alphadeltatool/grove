### Q1. `Map<String, List<String>>`로 Graph를 저장한다는 게 구체적으로 뭘 의미하나요?
A-B-C가 서로 연결된 작은 그래프 하나를 직접 예시 코드로 써보세요.

A가 B 랑 연결되어있고 B 는 C, C 는 A 랑 연결되어있을때 트리 구조와는 다르게 부모 자식 이런 관계가 아니고 서로상호간의 전혀 규율이 없는 관계일 경우

**[코치 보충] 코드로 옮기면:**
```java
Map<String, List<String>> graph = new HashMap<>();
graph.put("A", List.of("B", "C"));
graph.put("B", List.of("A", "C"));
graph.put("C", List.of("A", "B"));
```
"이름 → 이웃 목록" 매핑 그대로. 개념(계층 아니고 상호 관계)은 정확했음, 코드 번역만 빠졌던 부분.

### Q2. BFS와 DFS 각각을 자기 말로 설명하고, 같은 그래프에서 두 방법의 방문 순서가 왜 다른지 예시로 보여주세요.

BFS 는 넒이 중심이고 DFS 는 깊이 중심임 두개는 모두 GRAPH 의 순회를 위한 검색엔진임 
BFS 의 경우 연못에 돌뎅이 던지는것처럼 발아 시점부터 그 주변의 모든것을 훑는 거라고 생각하면되고 
DFS 의 경우는 한쪽의 가지를 모두 훑고 반대편 가지를 모두 훑는다 이렇게 생각하면됨

**[코치 정정] "검색엔진" → "순회(traversal) 알고리즘"이 정확한 표현.** 뭘 검색하는 게 아니라 모든 노드를 정해진 순서로 방문하는 방법이라서.

**[코치 보충] 순서가 다른 이유 — 예시 그래프 `A-B`, `A-C`, `B-D`, `C-E`:**
```
      A
     / \
    B   C
    |   |
    D   E
```
- BFS(큐, 넓게): A 처리 → 이웃 B,C를 큐에 넣음 → **B, C를 먼저 다 처리**(같은 거리라서) → 그다음 D, E → 순서: **A, B, C, D, E**
- DFS(스택/재귀, 깊게): A 처리 → B로 감 → B에서 더 갈 곳(D) 있으면 **D까지 끝까지 판 다음** 되돌아옴 → 그제서야 C로 감 → 순서: **A, B, D, C, E**

차이의 핵심: BFS는 "같은 거리에 있는 걸 다 처리하고" 한 층씩 내려가고, DFS는 "한 갈래를 끝까지 파고" 나서야 옆 갈래로 넘어감.

### Q3. 방문기록이 왜 반드시 필요한지, 그리고 왜 `ArrayList`가 아니라 `HashSet`을 쓰는 게 맞는지 설명해보세요.

방문 기록이 필요한 이유는 만약 방문한 기록이 없을경우 위에서 예를들면 a,b,c 의관계 a 를 추출하면 그의 관계된거를 put 해서 넣을텐데 
만약 에이를 방문했다고 빼지않으면 B 를 방문했을때 A의관계를 다시 집어넣기 떄문에 결국엔 Q 자체가 끝나지않는다
HASH SET 을 쓰는 이유는 ARRAYLIST 는 중복을 허용하지만 SET 은 중복을 허용하지 않기때문에 그런듯?

**[코치 정정] 절반만 맞음.** "중복 허용 안 함"은 `TreeSet`도 마찬가지라 `HashSet`을 특정하는 이유가 안 됨. 진짜 이유는 **속도**: `ArrayList.contains()`는 앞에서부터 하나씩 비교(O(n)), `HashSet.contains()`는 해시값으로 바로 위치 계산(O(1)). 그래프가 커질수록 "방문했나?" 확인을 매번 O(n)으로 하면 BFS/DFS 전체가 느려짐. 순서가 필요 없고(방문 여부만 확인하면 됨) 속도가 중요하니 `HashSet`이 맞는 선택.

### Q1. Graph를 메모리에 어떻게 저장할까 — 인접 리스트(adjacency list)
노드 하나가 몇 개랑 연결될지 정해져 있지 않으므로, 각 노드마다 "이웃 목록"을 **개수 제한 없는 리스트**(`ArrayList`/`List`)로 들고, 그 목록들을 **노드 이름(key) → 이웃 리스트(value)** 형태로 `Map`에 저장한다.
```java
Map<String, List<String>> graph = new HashMap<>();
graph.put("A", List.of("B", "C"));
graph.put("B", List.of("A", "C"));
graph.put("C", List.of("A", "B", "D"));
graph.put("D", List.of("C"));
```
- ✅ "개수 안 정해진 목록"이라는 조건에서 스스로 `ArrayList`를 떠올렸고, "이름→목록" 매핑이 필요하다는 데서 스스로 `Map`을 떠올림. 오늘까지 배운 도구만으로 완전히 구성됨(새 문법 없음).

### Q2. BFS와 DFS는 "Graph의 대안"이 아니라 "Graph를 훑어보는 두 방법"
처음엔 `BFS`/`DFS`/`Graph` 셋을 같은 층에서 비교하려다 막힘 → `Graph`는 데이터(명사), `BFS`/`DFS`는 그 데이터를 방문하는 방법(동사)이라는 범주 정정. (Tree의 in-order 순회와 같은 위치 — Tree를 훑어보는 한 방법이었던 것처럼.)
- **BFS(너비 우선)**: 연못 물결처럼, 가까운 데부터 골고루 퍼짐.
- **DFS(깊이 우선)**: 미로 탐험처럼, 한 방향으로 갈 데까지 가고 막히면 되돌아옴(백트래킹).
- 예시 그래프(`A-B`, `A-C`, `B-D`, `C-E`)로 직접 비교: **BFS 순서 = A,B,C,D,E** / **DFS 순서 = A,B,D,C,E**. B에서 D까지 완전히 판 다음에야 C를 보는 DFS와, B·C를 같은 거리라 먼저 같이 훑는 BFS의 차이를 손트레이스로 확인.

### Q3. 사이클 때문에 생기는 문제 — "방문 기록"이 왜 필요한가
`A:[B,C], B:[A,C], C:[A,B,D], D:[C]`에서 방문 여부를 기록 안 하고 BFS(Queue)를 돌리면, `A`를 처리하며 다시 `A`가 큐에 들어가는 식으로 **Queue가 절대 안 비고 무한루프에 빠진다**는 것을 큐 상태를 몇 바퀴 직접 손으로 따라가며 확인함(`[A]→[B,C]→[C,A,C]→[A,C,A,B,D]→...` 계속 늘어남).
