# Day 7 — Heap (힙) / 우선순위 큐

> 2026-08-12(이어서). 백지인출 + 대조채점 통합 정리.
> 서브젝트: "먼저 온 순서가 아니라 우선순위대로 처리하려면?"

## 큰 그림
```
Tree (일반 트리)
 ├─ BST — 왼쪽<나<오른쪽, "전체 정렬"에 특화, 탐색 O(log n)
 └─ Heap — 부모 vs 자식만 비교, "최댓값/최솟값 하나"에만 특화
     ├─ Max-Heap: 부모 ≥ 자식 → 루트 = 최댓값
     └─ Min-Heap: 부모 ≤ 자식 → 루트 = 최솟값
```
| | BST | Heap |
|---|---|---|
| 정렬 규칙 | 왼쪽<나<오른쪽(전체 정렬) | 부모 vs 자식만(형제는 무관) |
| 임의값 탐색 | O(log n) | O(n) |
| 최댓값/최솟값 | O(log n) | **O(1)**(루트) |
| 저장 방식 | 노드+참조 | **배열**(완전이진트리라 가능) |

`java.util.PriorityQueue`가 Heap의 실제 구현체. `TreeSet`/`TreeMap`은 BST 계열이지만 레드-블랙 트리(자동 균형)라서 일반 BST와 다름 — 우리 `MyBST`는 정렬된 순서로 넣으면 한쪽으로 치우쳐 O(n)까지 느려질 수 있다는 게 레드-블랙 트리가 필요한 이유.

## 백지 인출 + 대조 채점

### Q1. 우선순위 큐란?
FIFO(먼저 온 순서)가 아니라 **우선순위(급한 정도)**대로 처리되는 큐. 교과서 예시: 응급실 — 접수 순서가 아니라 중증도가 높은 환자가 먼저 처리됨.
- ❓ "식당 전화예약"으로 답했는데 방향이 모호해서 응급실 예시로 보강.

### Q2. Max-Heap/Min-Heap의 우선순위 기준은?
Max-Heap = 값이 클수록 우선순위 높음(루트=최댓값). Min-Heap = 값이 작을수록 우선순위 높음(루트=최솟값). 둘은 완전히 같은 구조에서 부모-자식 비교 방향만 반대로 설정한 것.
- ❓ "그냥 그렇게 설정하는 거냐"고 물어봄 → 맞다고 확인, Max-Heap/Min-Heap 예시 트리로 직접 검증(부모≥/≤자식이 형제·조카 관계엔 적용 안 됨 — BST보다 훨씬 느슨한 규칙이라는 것도 확인).

### Q3. 완전이진트리라서 왜 배열로 저장 가능한가?
각 노드에 "위→아래, 왼쪽→오른쪽" 순서로 번호를 매기면 그 번호가 그대로 배열 인덱스가 됨 — 참조 없이 인덱스 계산만으로 부모/자식을 찾을 수 있음.
- **왼쪽 자식 인덱스 = 부모×2+1, 오른쪽 자식 인덱스 = 부모×2+2, 부모 인덱스 = (자식-1)÷2**
- 표(부모0→자식1,2 / 부모1→자식3,4 / 부모2→자식5,6)로 직접 패턴 도출해서 이해함.
- ❓ "완전이진트리"를 "포화이진트리"(모든 자리가 꽉 참)로 착각해서 마지막 줄이 덜 채워진 걸 위반이라 생각함 → 완전이진트리는 "마지막 줄만 왼쪽부터 채우다 끝나도 됨(중간에 구멍만 없으면 됨)"으로 정정.
- 참고: BST는 in-order 순회하면 정렬되지만, Heap은 같은 순회를 돌려도 정렬 안 됨(형제 순서 보장이 없어서) — 순회 자체는 어떤 트리에도 가능하지만(재귀 구조 동일), 결과가 유용한지는 트리 종류에 따라 다름.

### Q4. 삽입(insert) — sift-up(부상)
새 값은 항상 배열 맨 끝에 넣는다 → 부모와 비교해서 규칙 위반이면 swap → 부모가 더 크거나(Max-Heap 기준) 루트에 도달할 때까지 반복.
- ✅ 방향(위로 올려야 함)과 "한 번으로 안 끝날 수 있다(계속 비교하며 여러 번 올라갈 수 있다)"는 것까지 직접 트레이스로 정확히 도출함. 예시: `50/30/40/10/20/35`에 `90` 삽입 → 40과 swap → 50과 swap → 루트 도달, 종료.

### Q5. 삭제(remove/extractMax) — sift-down(하강)
루트(최댓값)를 꺼낸 뒤, **배열 맨 끝 값을 루트 자리로 옮기고**, 두 자식 중 **더 큰 쪽**과 비교해서 내가 더 작으면 swap하며 아래로 내려보낸다 — sift-up과 방향만 반대, 원리는 동일. sift-up은 부모 하나랑만 비교하면 됐지만, sift-down은 자식이 둘이라 **"더 큰 자식"을 먼저 골라야 한다**는 게 다른 점 — 작은 자식이랑 바꾸면 오히려 규칙이 깨짐.
- ❓ `largerChildIndex()`에서 "오른쪽 자식이 없으면 -1(자식 없음)"이라고 잘못 판단 → 오른쪽만 없고 왼쪽은 있을 수 있으니 그 경우엔 왼쪽 자식 인덱스를 반환해야 한다고 정정.
- ❓ sift-down 종료 조건에 `>`(그냥 크다)를 씀 → Max-Heap 규칙 자체가 "부모≥자식"(같아도 됨)이므로 `>=`가 맞다고 정정. "부모==자식이면 왜 멈추냐"는 질문에 "이미 규칙을 만족하는 상태라 고칠 게 없다"로 답함.
- ✅ "왜 아래쪽(자식의 자식들)은 안 봐도 되냐"는 스스로 질문 → "sift-down이 지나간 자리 하나만 빼면 나머지는 원래부터 멀쩡한 힙이었으니, 매 단계 직속 자식들만 확인하면 충분하다"는 불변조건을 스스로 정확히 짚어냄.

## 구현 (`data-structure/heap/MyHeap.java`) — 완료 ✅
- **필드**: `int[] arrayInt`(고정 크기 20) + `size`.
- **인덱스 헬퍼 3개**(`parentIndex`, `leftChildIndex`, `rightChildIndex`): 표로 패턴 도출한 공식 그대로 힌트 없이 정확히 구현.
- **swap(i,j)**: 처음엔 매개변수 `i`,`j` 자체를 바꾸려 하거나(배열은 안 건드림), `if` 조건을 넣어 조건부로 바꾸려는 시도 등 여러 번 헤맴 → "읽기(지역변수 복사)"와 "다시 써넣기(`arrayInt[i]=...`)"를 구분 못 한 게 원인, BST 때 나왔던 것과 같은 패턴 → 조건 없는 3줄 temp-swap으로 정정.
- **insert()**: `swap()`의 두 번째 인자로 인덱스 대신 값을 넘기는 실수, swap 후 `current`를 갱신 안 해서 엉뚱한 위치를 계속 검사하는 실수 등을 거쳐 직접 완성.
- **largerChildIndex()**, **extractMax()**: 위 Q5 항목 참고. 전부 직접 완성.
- **실행 검증**: `50,30,40,10,20,35,90` 삽입 → `[90,30,50,10,20,35,40,...]`. `extractMax()`를 반복 호출하니 `90→50→40→35→30→20→10` 완벽한 내림차순으로 나옴(우선순위 큐 동작 확인).

## 오늘 배운 것 3줄
Heap = 부모-자식만 비교(형제 무관), 최댓값/최솟값 O(1) / 완전이진트리라 배열+인덱스공식(2i+1, 2i+2)으로 구현 / 삽입은 끝에 넣고 sift-up(부모와 비교), 삭제는 끝값을 루트로 올리고 sift-down(더 큰 자식과 비교)
